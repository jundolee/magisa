# 요구사항 정의서 — 개인 테크 블로그 아카이버

## 배경
사용자는 평소 많은 테크 블로그를 구독해서 읽는다. 관심 있는 블로그/사이트를 등록해두면, 매일 자동으로 새 글을 확인하고, 목록으로 모아 보여주며, 어떤 글을 읽었는지 관리할 수 있는 개인용 웹사이트가 필요하다.

## 핵심 기능

### 1. 소스(블로그) 관리
- 사용자가 팔로우하는 블로그/사이트를 등록할 수 있어야 한다.
- 단건 URL 등록뿐 아니라, **여러 개의 사이트 주소를 한 번에 붙여넣어 일괄 등록**할 수 있어야 한다. (기존 RSS 리더의 OPML 파일 내보내기는 없으므로, OPML 파싱 대신 단순 URL 목록 붙여넣기 방식으로 지원)
- 등록된 소스는 비활성화(일시중지)하거나 삭제할 수 있어야 한다.

### 2. 자동 수집
- 등록된 사이트를 **매일 1회 자동으로 확인**하여 새 글이 있으면 가져온다.
- 대부분의 기술 블로그는 RSS/Atom 피드를 제공하므로 **RSS/Atom 기반 수집을 우선**한다.
- RSS가 없는 사이트도 지원해야 하므로 **스크래핑(HTML 파싱) 방식도 함께 지원**한다. (사이트별 셀렉터 설정 필요)
- 동일한 글이 중복으로 쌓이지 않아야 한다 (중복 제거).

### 3. 글 목록/열람
- 수집된 글은 **제목, 요약, 썸네일(있는 경우), 출처 블로그, 발행일** 정보를 최신순으로 목록에 보여준다.
- 글 본문 전체는 저장하지 않는다 — 클릭하면 **원문 사이트가 새 탭으로 열린다.**
- 각 글은 **읽음/안읽음 상태**를 가지며, 사용자가 확인 후 관리할 수 있다.
  - 원문 링크를 클릭하면 자동으로 읽음 처리된다.
  - 사용자가 직접 안읽음으로 되돌릴 수 있어야 한다.

### 4. 디자인
- UI는 **SEED Design**(당근의 오픈소스 디자인 시스템, https://seed-design.io) 을 사용한다.
- React 기반 컴포넌트 시스템이며, 디자인 토큰(CSS 커스텀 프로퍼티) 기반 스타일링을 활용한다.

### 5. 배포
- 사이트는 **온라인에서 접근 가능**해야 한다 (로컬 실행이 아니라 실제 배포).

### 6. 인증
- 본인 전용 서비스이지만, **로그인 로직은 MVP에서는 만들지 않고 이후 단계에서 추가**하기로 결정했다.
- 즉, MVP는 별도 로그인 없이 접근 가능한 상태로 배포한다. (검색엔진 노출 방지 등 최소한의 보호만 고려)

## 개발 방식
- **MVP(필수 기능)만 먼저 구현**하고, 이후 요구에 따라 기능을 계속 추가할 수 있는 구조로 설계한다.
- 한 번에 모든 기능을 만들지 않는다 — 완성도보다 "핵심 흐름이 끝까지 동작하는 것"을 우선한다.
- 기술 스택(개발 언어/프레임워크)은 사용자가 팀(어시스턴트)의 추천을 따르기로 했다 → 상세 내용은 `architecture.md` 참고.

## 진행 방식 합의사항
- 실제 코드 구현 전, **계획/요구사항 문서를 먼저 작성**하고 이 폴더(`docs/`)에 누적한다.
- 구현 도중 사용자의 판단이 필요한 사항은 그때그때 확인받는다.
- 진행하면서 떠오르는 추가 아이디어는 중간에 제안한다 (예: Phase 2+ 후보 목록 참고 — `roadmap.md`).

## 범위 밖 (MVP 기준, 명시적으로 제외)
- 로그인/인증 (Phase 2 이후)
- 다크 모드
- 글 본문 전체 저장/인앱 리더
- 태그/카테고리 분류, 전문검색
- 이메일 다이제스트 등 알림 기능
